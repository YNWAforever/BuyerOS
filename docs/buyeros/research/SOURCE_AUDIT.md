## 6. Concrete gaps and state migration checklist

### Data and browser state

- `Store` is one whole React object initialized from `seed`. Every domain mutation is local `setS`. Extract the adapter/store boundary without replacing screens; preserve transient view state independently from server entities. **PROPOSED** adapter and query hooks may be introduced under `services/` and `features/` after approved contracts.
- `RecordBase.dataMode` is literally `'demo'`; some aliases such as `HumanReview`, `Approval`, `Suppression` omit tenant/project/mode/version fields altogether. Do not widen a global switch and reuse fixture state as live. Live client types must be generated or validated from the API, with runtime response-mode assertions and separately scoped caches.
- `Company` currently merges global identity, per-run AI fit/evidence, mutable human review, contact status, policy boolean, suppression, notes and activity. Normalize these into separately versioned entities and return an explicit presentation projection to preserve the drawer/table API.
- Every run shares `s.companies`; `rows` slices by `run.count`. Re-reviewing or changing any Company changes historical screens. Add run/company membership and immutable assessment per approved profile/run; never mutate historical evidence to make the latest run fit.
- `rawCandidates` is a static mapping, not ingestion deduplication. Define canonical domain/legal-company identity and record raw-to-canonical merge lineage; do not count contacts or aliases as companies.
- Current localStorage keys: `buyeros-demo-v1`, `buyeros-prefs-v1`, `buyeros-drafts-v1`. The first stores a sanitized synthetic Store; the second only locale; the third explicitly saves .example recipients and free text with warning. Reset removes only these keys. Live domain data must never be automatically imported from them. Keep demo reset separate from any server deletion action.
- Current restore validates only arrays/count 24, and separate draft read filters by `dataMode==='demo'` plus `.example` suffix. This is not a full safe schema parse or migration framework. Strengthen demo restore validation as an isolated UX task; never trust browser JSON as server authorization or budget state.
- Save locally blanks notes, normalizes owner to Willy, rewrites list names, excludes drafts/offers/files and strips part of certain activity text. This is an explicit sample convenience, not a reliable privacy redaction pipeline or server persistence model.
- `components/ui/sidebar.tsx` writes a `sidebar_state` cookie; Workspace does not load it. This is UI preference only and must not be reused for identity.

### Wizard and discovery

- Profile approval is one boolean; run profileVersion is `s.runs.length+1`, not an ICPVersion stored independently. Confirmed offer/profile revisions must be immutable and server-validated.
- Wizard accepts target 1–1000 but sample run clamps to 24. Contact-budget check lacks an explicit finite-number condition, unlike discovery budget. Server contract must validate finite nonnegative six-place decimal-string budgets and bounded integer target, regardless of browser input type.
- `startRun` equality check includes company/product/value/markets/requirements/types/advanced/roles, but not website, attached file or language preference. Fixed sample query strings never respond to these fields. Label current previews as templates; live plans must derive and show reviewed queries with provenance.
- `advanceRun` simulates stage progress and charges USD 0.60 at stages 3–6; seed spend is USD 6.60 from separate events. Both are synthetic assumptions.
