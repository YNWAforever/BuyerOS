## Private signed callback transaction

`services/delivery_callbacks.py` authenticates exact raw Svix bytes before parsing. Its server-owned retained endpoint binds the canonical workspace, original opaque account, reviewed contract and private key/expiry; default authority is absent. It is separate from new send admission. No HTTP route, production endpoint/key registry or provider account is configured by this source.

Only the original message provider_name=resend/account_reference/provider_ref is accepted under normal tenant RLS, and original liability must exist. JSON tenant/account/recipient/actor/address fields are not selectors or authority and are not copied to persistence. Provider data.email_id must be a canonical nonnil UUID. A callback without an original reference cannot create it or authorize a resend. Signed unsupported event types and duplicate JSON keys fail closed. Fresh attempt signatures are verified on every replay; original account/event/message/raw body hash cannot be rebound, including to another independently owned message. Global DB uniqueness conflicting with a hidden tenant is refused without identifying it.

The callback transaction locks the existing policy gate before the message. It writes a unique immutable event and forward-only message state in one nested transaction. email.sent maps to accepted, separately from email.delivered. Reviewed local mapping covers email.bounced/complained/failed/suppressed; suppression maps to failed plus an independent overlay, not an invented unsubscribe event. Bounce/complaint/suppression derive the canonical ContactPoint UUID from the original message, create at most one active delivery overlay, invalidate current approvals and quarantine contact material through the existing policy functions. Provenance references the immutable delivery event and retains the original canonical actor; it does not claim that a human took a new action. Later delivered/accepted events never remove the overlay. Existing manually reviewed opt-out remains the canonical policy workflow; no supplier email.unsubscribed contract is invented.

Status-only callback records remain possible after current outreach policy/approval revocation because the original submission still needs readback. They never submit, create an outbox, infer fees, release a reservation or settle a charge. Original unknown0.010000 full holds stay retained on every supported status, including delivered/failed. Duplicate/out-of-order receipt persistence is distinct from economic reconciliation. Endpoint expiry after actual writes rolls back event/state/overlay/approval/quarantine even when the caller catches refusal and commits its outer transaction.
