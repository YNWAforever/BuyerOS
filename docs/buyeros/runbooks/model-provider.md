## Request, provenance and domain boundary

The direct Responses candidate uses one code-owned HTTPS endpoint, an injected server-only credential and an explicit verified model/tokenizer/route. The request has no tools, stores no server-side response through `store:false`, sets strict JSON output and caps input tokens, output tokens, request/decoded-response bytes and duration. Source prose is only untrusted user data; prompt version is code-owned. Source URLs and instructions cannot change endpoint, tools, actor, company or requirements. Parse errors, refusal, tool calls, redirect, timeout, incomplete response and over-limit/mismatched usage remain unknown. The protocol was checked against [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) and [Responses migration](https://developers.openai.com/api/docs/guides/migrate-to-responses). `store:false` alone does not establish an account's retention or zero-data-retention agreement.

`PostgresModelReceipts` re-reads the shared fit core's current project/offer, approved active ICP, actor membership/startRun permission, account-research policy, run/buyer/company and evidence/source basis. Only server-resolved equal current data can be prepared. Model ID, route/prompt limits, canonical scope, complete request hash, contract/pricing hash, reservation, original operation/outbox and generation/backend/epoch are frozen. A native API role prepares; a distinct native worker role claims and finalizes. Neither owns the schema or bypasses forced tenant RLS. Worker INSERT and API UPDATE remain denied.

The durable claim commits before the model await. Database locks are not held across the request. Accepted/unknown/submitting receipts cannot reacquire a submission right; lost response preserves the hold, and lost write acknowledgement uses read-only reconciliation. Status reads the saved local response, not a supplier's native status guarantee or bill. Token usage and `resp_*` identify provenance only; they do not settle money or release a hold. A stale runtime epoch cannot persist/claim an accepted result.

The opt-in `LiveFitDomainRunner` shares the authoritative fit core. Graph checkpoints hold only IDs/flags. Fresh evidence must resolve to this company, source ID/hash, exact committed excerpt and revision, current purpose/retention, and non-inference data. Missing, stale, foreign or invented citations cannot Match. All trusted current evidence is considered, including hard exclusions omitted by a model. Offer/ICP/evidence/actor changes after verification block persistence. Model uncertainty is `needs_review`; every assessment retains `human_review` as the next action. Current hard exclusion bypasses the provider and reuses deterministic rejection after rechecking the basis. A checkpoint exclusion flag is not authority to produce a provider-free Match.

One immutable assessment can be reopened with model/prompt/route, request/response hashes, provider ref, token counts and offer/ICP/evidence/source revisions.
