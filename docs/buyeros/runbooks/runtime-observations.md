# C61-31 / C61-33a / C61-28a protected runtime observations

The workflow `buyeros-runtime-acceptance.yml` executes only by manual dispatch on main in the protected `buyeros-runtime-readonly` environment. It is source preparation, not remotely adopted or executed. Require reviewers with no self review and protected branches only before using it. It never migrates, links identities, changes roles, activates providers, pays, sends or promotes.

The job runs the existing bounded schema probe and the new `collect-workspace-observations.py` against reviewed existing accounts. Tokens and the database connection are environment-only secrets. A four-account packet binds each token's SHA256 to one owned, one foreign, one zero-membership and one already-revoked account. The last two require independently checked canonical mapping/revocation records; observing an empty directory or 404 alone does not prove those facts. The foreign denial is paired with the foreign account's success on the exact same project route. Neither an expired token's 401 nor an arbitrary 404 satisfies the denial contract. All seven requests use fixed GET routes. TLS verification is enabled, redirects/proxies/retries are disabled, and response bodies are capped at 1 MiB. The driver has a 5-second socket inactivity timeout; the protected workflow has a 5-minute total job limit. The standalone CLI does not provide a total wall-clock GET deadline. No response bodies or raw credentials appear in the observation receipt.

The API packet schema is `buyeros.workspace-api-target.v1`, with exactly these fields: `schema`, `source_sha`, `origin` (exact HTTPS origin, no path), `api_prefix` (exactly `/v1`, matching the existing same-origin proxy), `authorization_reference_sha256`, `accounts` and `token_sha256`. `accounts` has `owned` and `foreign`, each containing canonical `workspace_id`, `project_id` and unique `roles`. `token_sha256` has `owned`, `foreign`, `empty`, `revoked`. Keep account details and the authorization record in the private packet, not source control. Denials use the actual API's top-level `code`, `message`, `request_id`, `retryable` envelope.

Before any read, `runtime-observation-packet.py prepare` verifies both packets against `GITHUB_SHA`, `BUYEROS_G0_CONTRACT_SHA256`, `BUYEROS_SCHEMA_CONTRACT_SHA256` and the protected `BUYEROS_RUNTIME_READ_SCOPE_SHA256`. The schema contract uses the existing typed `SchemaContract`, `candidate_runtime` mode and independently reviewed matching target proof. A fixture label, a PR context, an absent target proof or a changed digest fails before materializing files or issuing requests. These checks do not establish that the protected DSN is the actual deployed sensitive DSN; the external deployment-to-database binding still needs its own readback.

Detailed stdout/stderr stay in private runner logs and are never artifact inputs. Since the workflow itself is public, every execution also requires an exact `BUYEROS_RUNTIME_WORKFLOW_REQUEST_SHA256` authorizing disclosure of the job's existence/conclusion. Its payload has the same three digests below and `artifact_scope: public-workflow-status-v1`. Missing or mismatched authorization fails before any read.

Artifact publication defaults to false. If selected, preparation also requires the separate protected scope `public-redacted-observations-v1` and an exact `BUYEROS_RUNTIME_PUBLICATION_REQUEST_SHA256`. It is the canonical SHA256 (sorted keys, compact JSON) of:

```json
{"source_sha":"<40 lowercase hex>","api_contract_sha256":"<64 lowercase hex>","schema_contract_sha256":"<64 lowercase hex>","artifact_scope":"public-redacted-observations-v1"}
```

Compute this request with `publication_request` and `canonical_digest` in the packet tool, review the concrete target/source/publication scope, then configure the approval only through the protected environment. A dispatch boolean is not authorization. This repository is public: artifact publication and Sigstore provenance disclosure require their own scoped approval. The workflow has not been dispatched and no approval settings have been provisioned by this source change.

Only the fixed redacted summary `artifacts/runtime-observations.json` may be attested/uploaded. Private packets and the raw schema receipt remain in the ephemeral runner directory and are never artifact inputs. The public artifact name is `buyeros-runtime-observations`; it has a distinct schema from a promotion bundle and always includes `promotable: false`. Missing/failed reads remain failed. The final workflow step checks the original schema/API/summary step outcomes, so `continue-on-error` preserves diagnostic collection without making the run green.

G0 remains blocked on the exact deployed DB binding, canonical mapping, real browser workspace/reload/retry canary and independent compatible frontend+API rollback. GN/GA/GS require their existing separate receipts. Do not copy these partial observation statuses into `workspace_canary`, `rollback`, `neon` or any `accepted` field.

Local required CI runs all new controls with native discovery/JUnit joining, zero skips, plus the retained promotion controls. Those results prove source/owned transport behavior only. The control asserting that partial observations never enter `promote-candidate.py` applies even if the observation bytes have a valid signer attestation.
