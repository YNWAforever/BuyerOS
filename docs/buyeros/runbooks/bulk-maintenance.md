# Bulk maintenance and capability recovery

This runbook describes local C61-23 behavior. Real account/provider, production readback and human screen reader/UAT are separate gates.

1. Choose the workspace/project, current buyer filters, operation and human owner/list name. Enter a reason and any exact exclusions. Read the frozen count, operation, target, reason, filter chips, requested exclusion count and digest. Technical details reveal the exact IDs and original basis. The count is the frozen selected count; it does not promise every row is still eligible at execution.
2. A ready preview lasts 15 minutes. The server checks actor, current membership, workspace/project, digest, version and TTL again. Expiry disables new confirmation and clears its checkbox. Start a new preview, returning keyboard focus to Preview, to re-read current versions. Changing the owner/filter/exclusions requires a new preview; scope changes mount the selected scope with a fresh confirmation.
3. Up to 10000 matching rows can be frozen; 10001 is refused. Up to 100 execute synchronously; 101+ create a durable job. Progress, resume URL and results are read from the real job. Result pages request only the current 20 rows; the full download streams in bounded pages. Refresh and automatic polling do not announce identical progress repeatedly.
4. An unknown preview retains its exact frozen body/key. An unknown execution retains its exact digest/body/key/version: reconcile that submission or recheck its manifest. Its recovery is not a new confirmation and is not prevented by the display deadline. Do not start a replacement while the execution remains unknown; never resubmit accepted/unknown provider operations.
5. For partial completion, choose Preview failed rows with current versions. The child manifest contains only non-success rows and needs a new digest confirmation. In the required DB case, 80 updated rows and one unchanged row remain untouched while the 20 conflict rows are re-read and updated by the child. Successful rows are never replayed. Cancellation affects pending rows only.

Settings shows current DB-derived membership roles and the server's five capability statuses and checked times. A failed/incomplete read shows unavailable rather than a ready or disconnected guess. Refresh retries only this read. Ask a workspace administrator to verify the provider selection, price, approved allowance and authorized connection test. No capability read activates a provider, spends allowance or sends a message. Mailbox/CRM native delivery retains its separate C61-20/30 gate; approved export remains independent.

Required local verification separates built HTTP/owned-PG keyboard and zoom checks from the existing demo responsive parity. en/zh-HK expiry/settings cases use desktop/390px, real fixture API responses and no page overflow. These checks do not replace human screen reader task completion or production readback.

Rollback: revert the C61-23 UI/helper changes. Keep existing server expiry, frozen manifest immutability, current-role checks, successful-row exclusion, durable exact-intent recovery and audit/history. No migration, UUID/FK, RLS or provider trust change is part of this task.
