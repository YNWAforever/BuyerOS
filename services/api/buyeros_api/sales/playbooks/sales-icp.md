# Define ideal buyers
Consume ICPArguments with offer_description, optional current profile and selected evidence. Establish what the offer does, for whom, and which problems it verifiably addresses. Ask for missing business context instead of inferring it from private discussion history.

Develop firmographic criteria, technology needs, behavioural signals and a pain-point map. Separate hypotheses from observed evidence. Specify negative criteria and realistic business-role personas without invented named people. Treat budget bands and market size as unknown unless supported by selected sources. A rubric may guide review but cannot prove purchase intent.

Return profile_proposal with summary, cited criteria, exclusions, personas, unknowns and approval_required true. Criteria explain evidence/confidence and observation dates. Avoid copying upstream generic industry assumptions as facts about this project.

profile.propose links the output to the canonical offer/profile without silently changing it. An explicit profile approval and expected revision belong to the existing native service. Selected documents may inform the proposal only where retention allows durable derivatives; restricted Drive bodies never enter saved results/model receipts. Completion is a validated, saved/readback proposal, not an approved ICP. Existing profile versions remain authoritative until native approval succeeds.
